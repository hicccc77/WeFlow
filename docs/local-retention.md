# 本地消息与朋友圈留存

侧栏的「消息留存」和「朋友圈留存」用于保存独立的本地副本。两项功能默认关闭，分别由你主动开启；它们读取当前账号在本机可访问的内容，不修改微信源数据库，也不安装防撤回或防删除触发器。原有防撤回、防删除功能保持独立。

留存只能保住已经读到的内容：没有捕获到的消息、在首次读取前已经删除或不可见的朋友圈，无法靠留存恢复。它也不是手机或微信云端全部历史记录的备份。

## 使用前准备

1. 先完成 WeFlow 的数据库连接和账号选择，确认「聊天」或「朋友圈」能正常读取内容。图片等媒体还需要对应的[第三方组件](third-party-components.md)能够正常工作。
2. 保持微信和 WeFlow 运行。退出 WeFlow 后不会继续捕获；再次运行时只能读取仍在本机可用的内容。
3. 在对应留存页开启开关。关闭开关会停止后续留存，已有副本仍可查看。

## 消息留存

打开侧栏「消息留存」，开启「自动留存消息」。开始运行时会读取会话中近期可用的消息，之后持续检查更新，不会补齐全部历史聊天。

- **已留存原文**：消息在撤回前已被读到，会保留当时的副本。
- **未捕获原文**：只读到了撤回提示，原消息已经不可用。该条记录表示发现过撤回，不表示恢复了原文。
- **检测到撤回**：时间是 WeFlow 识别该提示的时间，可能晚于实际撤回时间；首次扫描也可能发现较早的撤回提示。

可用搜索查找会话、发送者或消息正文，也可勾选「只看撤回」。留存依赖扫描时机和数据库可读性，不能保证捕获每一条消息。

### 消息媒体范围

目前会尝试为可读取、可解密的本机图片，以及已有本地文件的表情保存独立副本。尚不保存视频、语音和附件的完整文件内容。看到了消息文字或类型提示，不代表对应媒体文件已经保存；以每条记录的媒体状态为准。

## 朋友圈留存

1. 在微信中打开、刷新朋友圈，让可见的新内容进入本机缓存；需要较早的动态时，也要先在微信中浏览到它们。
2. 打开侧栏「朋友圈留存」，开启「自动留存朋友圈」。首次整理会分批读取本机已经存在的动态。
3. 需要立即重新检查时，点击「立即扫描」。此按钮需要先开启自动留存；「刷新列表」不会重新扫描微信数据库。

文字通常会先出现，图片和视频在后台尝试保存。当前查看或搜索到的动态会优先处理媒体，但原件可能已过期、无法下载、格式不支持或超过大小限制，不能保证补齐。

动态正文、曾经读到的点赞和评论，以及不同读取结果的快照会独立留存。它们可能与微信当前显示不同；「最近读取」只是再次读到本机缓存的时间，不证明对方此刻仍公开这条动态。

### 朋友圈媒体状态

| 页面提示 | 含义 |
| --- | --- |
| 已保存图片／视频／实况照片 | 已有对应的本地原件副本；能否播放还取决于设备支持的格式。 |
| 仅保存缩略图 | 原件尚未保存，当前显示的是缩略图，不代表高清图片、完整视频或实况视频已经留存。 |
| 排队保存中 | 自动留存已开启，正在等待后台尝试；退出应用或关闭开关会暂停后续处理。 |
| 未保存 | 尚未获得可用文件，文字和其他成功保存的内容仍会保留。 |

顶部「已保存原件」只统计完整原件；「原件未保存」包括仅有缩略图的项目。视频和实况视频不会自动播放。当前每个朋友圈媒体文件的留存上限为 128 MiB。

朋友圈媒体可能需要从微信媒体服务下载，因此获取媒体时需要网络。归档页面的图片和视频预览仅使用归档内的本地副本，不会直接加载动态中的远程图片地址，也不会把正文作为 HTML 执行。

## 保存位置与备份

点击对应页面的「打开保存目录」即可查看当前账号的归档。不同账号的留存相互隔离，媒体是独立文件，不依赖原缓存一直存在。关闭留存不会清空已保存数据，归档也不会按时间自动过期。

留存文件可能包含可直接读取的消息、评论及媒体，请按自己的隐私需要保管和备份。自动留存不是磁盘备份；手动删除归档、卸载时清理应用数据或磁盘损坏，仍可能造成丢失。备份前先关闭两项留存并退出 WeFlow，再复制完整保存目录。
